# Decisions log

One line each: **decision** — reason — alternative considered.

- **Full mode (Docker stack)** — `docker info` responds, so SPEC 0.5 says full mode — lite mode (SQLite adapters).
- **Run on native Windows, not WSL** — Claude Code was started from Git Bash on Windows; installing/using WSL was out of scope (no admin) — move repo into WSL later for speed.
- **Remapped host ports (Postgres 55432, Redis 56379, web 3100)** — 5432 and 3000 were already in use by other local projects — stop the user's other containers (rejected: not ours).
- **API and worker run as host Python processes against Docker services** — faster iteration on Windows; compose also defines `api`/`worker` services under the `apps` profile — run everything in containers.
- **Single root `pyproject.toml` with hatch-mapped packages instead of a multi-member uv workspace** — one lockfile, one venv, less overhead in a 4 h run; package boundaries are still the SPEC 19 folders — one pyproject per package.
- **Python 3.12 via `uv python pin 3.12`** — system Python is 3.13; SPEC requires 3.12 — use 3.13.
- **Makefile delegates to `tasks.py`** — same commands on Windows and Linux; `make` exists here but scripts must be portable — shell recipes.
- **mypy non-strict in this run** — time; strict mode is a Phase B task — strict now.
- **Azurite's well-known public dev key is in `.env.example`** — it is Microsoft's documented emulator key, not a secret — generate a custom Azurite account.
- **Drop the 39 exact-duplicate IMR rows, then enforce unique ReferenceID** — the duplicates are byte-identical (0 conflicting); the uniqueness check still stops the load on conflicting duplicates — treat any duplicate as a failed load (would force the synthetic fallback and lose the real data).
- **IMR download uses a non-default User-Agent and plain GET** — S3 pre-signed URL rejects HEAD (403) — none.
- **PII scan of 42k Findings uses regex recognizers only; Presidio is used at runtime on letters** — spaCy NER over ~12M words would take ~20 min overnight — run Presidio over the whole dataset (Phase B).
- **Precedent chunks drop the reviewer "Credentials/Qualifications" boilerplate** — it is identical across cases and would dominate keyword/vector similarity — keep full text.
- **Precedent chunks split at ~300 words (≈400 tokens) with 40-word overlap** — SPEC says ~400 tokens — token-exact splitting with a tokenizer.
- **eCFR chunks merge short sibling paragraphs within the same top-level paragraph; median chunk is below 150 tokens for some sections** — many CFR paragraphs are short and merging across top-level paragraphs would blur citations — strict 150-token minimum.
- **eCFR fetched sections for 45 CFR 149: 149.110, 149.120, 149.130, 149.410, 149.420** — SPEC asks for "emergency services and patient protections" only — whole Part 149 (mostly IDR procedure text).
- **GovInfo bulk XML fallback is not automated** — different volume-level structure; the eCFR API worked — automate it in Phase B.
- **Deadline rules resolve their citation by a required phrase (`must_contain`) instead of hard-coding chunk IDs** — chunk IDs depend on parser details; a rule whose phrase is not found is disabled — hard-coded IDs.
- **Deadline trigger = the date printed on the notice** — regulations count from receipt; the notice date is the earliest (most conservative) reading — assume a mailing delay.
- **Medicare Advantage reconsideration window = 60 calendar days** — that is the current text of 42 CFR 422.582(b) as fetched (an older 65-day figure was not used) — n/a.
- **Synthetic letters use fictional insurers ("Example Health Plan", ...), Testville, ZIP 00000** — hard rule 8 and no impersonation of real organizations — realistic insurer names.
- **Gold letters use a different template family and reason-phrase bank from train/validation** — SPEC D4 generalization requirement — same templates.
- **Job table doubles as the transactional outbox** — inserting the job row in the same transaction as the state change gives the outbox guarantee without a relay process; Service Bus in Phase C gets a relay — separate outbox + relay table now.
- **Step output and state transition commit in one transaction** — makes crash recovery exact (both or neither); replay returns cached outputs — separate commits.
- **Per-case data key (AES-256-GCM) wrapped by the master key; the purpose string is bound as AAD** — envelope encryption per SPEC 12; AAD stops ciphertext being reused across fields — one global key.
- **Presidio PERSON hits are filtered (multi-word, no digits/newlines, no organization words)** — en_core_web_sm tagged insurer names and "Tel 555-01xx" as people, which broke the leak gate — larger spaCy model (slow to download).
- **Leak gate also blocks untokenized high-precision shapes (email, SSN, phone, ZZTEST IDs)** — fail closed even for identifiers the detector missed — known-values only.
- **Writer cites a rule only if the rule text supports the sentence (key-term overlap ≥ 0.25); legal sentences without support are dropped** — "if a rule is unknown, the letter says less" (hard rule 3) — always include playbook grounds.
- **Deadline sentence uses a per-rule paraphrase stored next to the rule (`letter_text`)** — keeps the sentence verifiably supported by the cited paragraph and avoids claiming the user is still within time — a computed "you are within N days" sentence.
- **Precedent sentences quote the IMR reviewer's favorable conclusion sentence, with fixed non-binding prefix** — grounded by construction, passes the support checker — paraphrase.
- **Integration tests use the dev database (data already loaded); queue/state tests use `appeal_test`** — loading 42k IMR rows per test session is slow — a fully separate seeded test DB (Phase B).
- **OTel console exporter writes to `var/logs/traces.jsonl`** — keeps the console readable — stdout.
- **Ruff ignores B023/B904/B905/B017** — lambdas are executed synchronously inside the loop; others are stylistic — rewrite.
- **Retrieval gold relevance is defined by text/metadata filters, never by the retriever** — avoids circular labels; questions whose phrases do not resolve are dropped — hand-picked chunk IDs.
- **recall@5 normalized by min(|relevant|, 5)** — precedent questions have hundreds of relevant cases; plain recall@5 would be meaningless — hit@5.
- **Keyword search uses OR between terms (`websearch_to_tsquery` with "or")** — AND semantics returns nothing for natural-language questions — plainto_tsquery (AND).
- **Precedent embedding text = treatment category + subcategory + chunk text** — gives the vector side the same metadata signal the keyword side has — text only.
- **M1 calibration and ask-user threshold come from grouped (by reason template) stratified out-of-fold predictions, with temperature scaling** — validation letters share templates with training letters (validation macro-F1 ≈ 1.0, useless for calibration); grouped OOF predicts unseen phrasing (OOF F1 0.84 ≈ gold 0.84) — isotonic on validation (tried first: gold ECE 0.13, threshold meaningless).
- **M1 serving threshold overrides CLASSIFIER_THRESHOLD when the model is loaded** — SPEC 10 M1 threshold rule — single global threshold.
- **M2 serving variant is the shortcut-removed TF-IDF model** — the user's text never contains reviewer boilerplate — serve the full model.
- **M2/M3 time split: Y = most recent full year (2025); partial 2026 excluded** — SPEC 10 M2 split rule — include partial year.
- **M3 HistGradientBoosting groups categories with < 10 rows (max 250 levels)** — native categorical support is capped at 255 levels — target encoding.
- **Model binaries (`*.joblib`) are git-ignored; cards, metrics and configs are committed** — `make train` reproduces them in ~20 s — commit binaries.
- **Next.js 15 + React 19 stable; ESLint/Prettier/Vitest not configured overnight** — time; `tsc --noEmit` + `next build` run in CI — full lint setup (Phase B).
- **Playwright uses the locally installed Chrome (`channel: chrome`) and skips the browser download** — keeps network use to package registries — `npx playwright install`.
- **Root package.json has no npm workspaces** — workspace hoisting fought with the React 19 peer ranges; scripts delegate with `npm --prefix apps/web` — workspaces.
- **Per-case Postgres advisory lock around each job** — two workers (or a redelivered job) on the same case raced on state transitions in testing; the lock gives per-case ordering like Service Bus sessions — rely on unique-constraint retries only.
- **SSE keeps streaming past stale terminal events during replay** — a client reconnecting from event 0 saw an old NEEDS_CATEGORY and disconnected although the case had moved on — end the stream on the first terminal event.
- **Eval pipeline auto-confirms facts and accepts the suggested category** — measures the system, not a simulated user's corrections — skip NEEDS_CATEGORY cases.
- **Red-team "behavior changed" = banned output phrases (word-boundary), category differs from the clean twin, or the case did not finish** — mechanical, reproducible definition — manual review.
- **D3 uses the newest PUF (2027 release, plan-year 2025 data), individual-market QHP sheet, issuer level; denials = in-network + out-of-network** — SPEC asks for issuer-level claims/denials/appeals; SHOP and dental sheets skipped — plan-level rows.
- **Insurer insights flag turned on (`FEATURE_INSURER_INSIGHTS=true`) because D3 loaded** — SPEC fallback hides it only when D3 fails — keep hidden.
